## 📊 四个核心状态

### 1. 待处理（Pending）
**定义**：任务已创建，等待开始执行
**触发条件**：
- 新任务创建时
- 返工任务重新分配时

**状态特征**：
- 任务已明确，但未分配具体执行者
- 等待用户确认或角色认领
- 优先级已确定

**示例**：
- "手数分析功能"任务刚创建
- "拆牌罚分层级"功能等待提示词设计

### 2. 进行中（In Progress）
**定义**：角色正在执行任务
**触发条件**：
- 角色开始执行任务时
- 用户确认后开始执行时

**状态特征**：
- 有明确的执行者（提示词工程师/代码执行者）
- 任务正在执行中
- 有中间产出物

**子状态**：
- **进行中（提示词）**：提示词工程师正在设计
- **进行中（代码）**：代码执行者正在实现

**示例**：
- 提示词工程师正在撰写手数分析的提示词
- 代码执行者正在实现手数分析功能

### 3. 测试中（Testing）
**定义**：测试验证者正在测试任务成果
**触发条件**：
- 代码执行者完成修改后
- 测试验证者开始测试时

**状态特征**：
- 测试验证者正在执行测试
- 有测试用例和测试脚本
- 测试结果待定

**示例**：
- 测试验证者正在运行手数分析的功能测试
- 测试验证者正在验证AI决策准确性

### 4. 已完成（Completed）
**定义**：测试通过，任务正式交付
**触发条件**：
- 所有测试通过时
- 用户确认验收时

**状态特征**：
- 测试覆盖率达标
- 功能符合预期
- 文档完整
- 可以交付使用

**示例**：
- 手数分析功能测试全部通过
- 用户确认验收，功能正式上线

## 🔄 状态流转规则

### 标准流转路径
```
待处理 → 进行中（提示词）→ 进行中（代码）→ 测试中 → 已完成
```

### 返工流转路径
```
测试中 → 待处理（返工）→ 进行中（提示词）→ 进行中（代码）→ 测试中 → 已完成
```

### 状态触发条件

#### 从"待处理"到"进行中"
- **提示词工程师**：用户确认需求后开始设计
- **代码执行者**：用户明确说"你现在改/你来改/去改"后开始实现

#### 从"进行中（提示词）"到"进行中（代码）"
- 提示词文档完成并经过用户确认
- 代码执行者接收提示词文档

#### 从"进行中（代码）"到"测试中"
- 代码执行者完成修改并自测通过
- 测试验证者开始执行测试

#### 从"测试中"到"已完成"
- 所有测试用例通过
- 测试覆盖率达标
- 用户确认验收

#### 从"测试中"到"待处理（返工）"
- 测试发现问题
- 问题返回给提示词工程师重新设计

## 👥 状态更新责任

### 提示词工程师
**负责更新**：
- "进行中（提示词）"状态
- "待处理（返工）"状态

**更新时机**：
- 开始设计时：状态变为"进行中（提示词）"
- 设计完成时：状态变为"待处理"（等待代码执行）
- 收到返工任务时：状态变为"待处理（返工）"

### 代码执行者
**负责更新**：
- "进行中（代码）"状态
- "测试中"状态（提交测试时）

**更新时机**：
- 开始实现时：状态变为"进行中（代码）"
- 实现完成时：状态变为"测试中"

### 测试验证者
**负责更新**：
- "测试中"状态
- "已完成"状态

**更新时机**：
- 开始测试时：确认状态为"测试中"
- 测试通过时：状态变为"已完成"
- 测试失败时：状态变为"待处理（返工）"

## 📋 状态跟踪机制

### 任务看板
使用任务看板跟踪所有任务的状态：

**待处理列**：
- 新创建的任务
- 返工任务

**进行中列**：
- 正在执行的任务
- 分为提示词和代码两个子列

**测试中列**：
- 正在测试的任务
- 测试验证者负责

**已完成列**：
- 测试通过的任务
- 正式交付的任务

### 状态更新规则
1. **及时更新**：状态变化时立即更新
2. **明确责任**：只有负责的角色才能更新状态
3. **记录变更**：记录状态变更的时间和原因
4. **可视化**：任务看板实时显示状态

## 🚨 异常状态处理

### 阻塞状态
**定义**：任务因外部因素无法继续
**处理**：
1. 标记为"阻塞"状态
2. 记录阻塞原因
3. 寻求解决方案
4. 解除阻塞后继续

### 挂起状态
**定义**：任务因优先级调整暂时挂起
**处理**：
1. 标记为"挂起"状态
2. 记录挂起原因
3. 优先级恢复时重新激活

### 取消状态
**定义**：任务因需求变更取消
**处理**：
1. 标记为"取消"状态
2. 记录取消原因
3. 归档任务记录

## 📈 状态监控指标

### 流程效率指标
1. **平均处理时间**：任务从"待处理"到"已完成"的平均时间
2. **返工率**：测试失败导致返工的比例
3. **阻塞率**：任务被阻塞的比例

### 质量指标
1. **测试通过率**：测试通过的任务比例
2. **缺陷密度**：每千行代码的缺陷数
3. **回归缺陷率**：修改引入新缺陷的比例

### 监控方法
1. **每日站会**：同步任务状态和问题
2. **周报分析**：分析状态流转效率
3. **持续改进**：基于数据优化流程

## 🎯 状态管理最佳实践

### 1. 保持状态简洁
- 只使用四个核心状态
- 避免状态过多导致混乱
- 状态定义清晰明确

### 2. 明确责任边界
- 每个状态有明确的责任人
- 状态更新需要责任人确认
- 避免越权更新状态

### 3. 及时同步信息
- 状态变化时立即通知相关角色
- 保持任务看板实时更新
- 定期同步任务进展

### 4. 持续优化流程
- 定期回顾状态管理效果
- 收集角色反馈，优化流程
- 基于数据驱动改进

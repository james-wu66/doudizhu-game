## 🚨 错误分类

### 1. 代码错误（Code Errors）
**定义**：代码实现过程中的错误
**类型**：
- **语法错误**：代码不符合语法规则
- **运行时错误**：代码执行过程中出错
- **逻辑错误**：代码逻辑不符合预期

**示例**：
- JavaScript语法错误：`function foo() {` 缺少闭合括号
- Python运行时错误：`IndexError: list index out of range`
- 逻辑错误：AI决策算法返回错误结果

### 2. 设计错误（Design Errors）
**定义**：提示词设计或策略设计不合理
**类型**：
- **需求理解错误**：没有正确理解业务需求
- **策略设计缺陷**：AI策略设计不合理
- **提示词表述不清**：提示词文档表述模糊

**示例**：
- 手数分析算法设计错误，导致计算结果不准确
- 拆牌罚分层级设计不合理，导致AI决策偏差
- 提示词文档没有明确边界条件

### 3. 测试错误（Test Errors）
**定义**：测试过程中的错误
**类型**：
- **测试用例不全**：没有覆盖所有场景
- **测试环境问题**：测试环境配置错误
- **测试数据问题**：测试数据不准确

**示例**：
- 没有测试空手牌的边界情况
- Jest配置错误导致测试无法运行
- 测试数据不包含极端牌局

## 🔄 错误处理流程

### 标准处理流程
```
发现问题 → 问题分类 → 责任判定 → 问题修复 → 验证修复 → 关闭问题
```

### 详细步骤

#### 步骤1：发现问题
**发现者**：测试验证者（主要）、代码执行者（自测）、用户（反馈）
**发现方式**：
- 自动化测试失败
- 手动测试发现问题
- 用户反馈问题

**问题记录**：
1. 问题描述：清晰描述问题现象
2. 复现步骤：如何重现问题
3. 预期结果：应该出现的结果
4. 实际结果：实际出现的结果
5. 环境信息：操作系统、浏览器、版本等

#### 步骤2：问题分类
**分类标准**：
- **代码错误**：问题源于代码实现
- **设计错误**：问题源于提示词设计
- **测试错误**：问题源于测试过程

**分类依据**：
1. 分析问题根源
2. 检查相关代码和设计文档
3. 确定问题归属

#### 步骤3：责任判定
**判定规则**：
- **代码错误** → 代码执行者负责修复
- **设计错误** → 提示词工程师负责重新设计
- **测试错误** → 测试验证者负责修改测试

**判定流程**：
1. 测试验证者提交问题报告
2. 提示词工程师分析问题根源
3. 确定责任角色
4. 分配修复任务

#### 步骤4：问题修复
**修复要求**：
- **代码错误**：修改代码，确保不引入新问题
- **设计错误**：修改提示词文档，重新设计策略
- **测试错误**：修改测试用例，完善测试覆盖

**修复流程**：
1. 责任角色接收问题报告
2. 分析问题原因
3. 制定修复方案
4. 执行修复
5. 自测验证

#### 步骤5：验证修复
**验证方式**：
- 重新运行相关测试
- 执行回归测试
- 用户验收测试

**验证标准**：
- 问题不再出现
- 没有引入新问题
- 功能符合预期

#### 步骤6：关闭问题
**关闭条件**：
- 问题已修复
- 验证通过
- 相关文档已更新

**关闭流程**：
1. 更新问题状态为"已修复"
2. 记录修复方案和验证结果
3. 归档问题记录

## 🔧 具体错误处理示例

### 示例1：代码错误 - 语法错误
**问题**：JavaScript函数缺少闭合括号
**处理流程**：
1. 测试验证者发现测试失败
2. 分析错误日志，定位到语法错误
3. 判定为代码错误，责任在代码执行者
4. 代码执行者修复语法错误
5. 重新运行测试，验证修复

### 示例2：设计错误 - 策略缺陷
**问题**：手数分析算法计算错误
**处理流程**：
1. 测试验证者发现AI决策不符合预期
2. 分析算法逻辑，发现设计缺陷
3. 判定为设计错误，责任在提示词工程师
4. 提示词工程师修改提示词文档
5. 代码执行者根据新文档重新实现
6. 测试验证者重新测试

### 示例3：测试错误 - 测试用例不全
**问题**：没有测试空手牌边界情况
**处理流程**：
1. 用户反馈空手牌时程序崩溃
2. 分析发现测试用例未覆盖该场景
3. 判定为测试错误，责任在测试验证者
4. 测试验证者补充测试用例
5. 代码执行者修复空手牌处理逻辑
6. 测试验证者运行补充的测试

## 📊 错误统计与分析

### 错误统计指标
1. **错误数量**：各类错误的数量
2. **错误趋势**：错误数量的变化趋势
3. **修复时间**：平均修复时间
4. **返工率**：因错误导致的返工比例

### 错误分析方法
1. **根因分析**：分析错误产生的根本原因
2. **趋势分析**：分析错误数量的变化趋势
3. **分类分析**：分析各类错误的比例
4. **影响分析**：分析错误对项目的影响

### 持续改进
1. **预防措施**：基于错误分析制定预防措施
2. **流程优化**：优化错误处理流程
3. **培训提升**：针对常见错误进行培训
4. **工具改进**：改进测试工具和开发环境

## 🚨 紧急错误处理

### 紧急错误定义
- 影响核心功能的严重错误
- 导致系统崩溃的致命错误
- 影响用户体验的关键错误

### 紧急处理流程
1. **立即响应**：立即停止当前工作，处理紧急错误
2. **快速定位**：快速定位问题根源
3. **临时修复**：实施临时修复措施
4. **根本解决**：制定根本解决方案
5. **验证确认**：验证修复效果
6. **总结归档**：总结经验教训

### 紧急错误沟通
1. **即时通知**：立即通知相关角色
2. **状态同步**：实时同步处理进展
3. **决策记录**：记录紧急决策过程

- 建立完善的测试体系
- 鼓励角色间相互审查
- 建立用户反馈机制

- 明确责任分工
- 保持沟通畅通

### 3. 彻底解决
- 追根溯源，不表面修复
- 修复后进行回归测试
- 更新相关文档

### 4. 持续改进
- 定期回顾错误处理效果
- 分析错误模式，制定预防措施
- 优化错误处理流程

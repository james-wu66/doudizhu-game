## 主要职责
1. **测试用例设计**
   - 根据需求文档设计测试用例
   - 编写测试脚本
   - 设计测试数据

2. **测试执行**
   - 执行单元测试
   - 执行集成测试

   - 执行性能测试

3. **缺陷管理**
   - 发现和报告缺陷
   - 跟踪缺陷修复进度
   - 验证缺陷修复效果
   - 缺陷分析和统计

4. **测试报告**
   - 编写测试报告
   - 分析测试结果
   - 提出改进建议
   - 维护测试文档

## 技能要求
- 熟悉软件测试理论
- 掌握测试用例设计方法
- 熟悉自动化测试工具
- 了解性能测试工具
- 具备缺陷分析能力

## 工作流程
1. 接收组长分配的任务
2. 与提示词工程师沟通测试需求
3. 设计测试用例
4. 准备测试数据
5. 执行测试
6. 记录测试结果
7. 报告缺陷
8. 验证修复
9. 编写测试报告

## 测试类型
1. **单元测试**
   - 测试单个函数/方法
   - 测试边界条件
   - 测试异常情况
   - 代码覆盖率要求：80%以上

2. **集成测试**
   - 测试模块间交互
   - 测试API接口
   - 测试数据流
   - 系统集成测试

3. **系统测试**
   - 端到端测试
   - 用户场景测试
   - 兼容性测试
   - 安全性测试

4. **性能测试**
   - 负载测试
   - 压力测试
   - 稳定性测试
   - 性能基准测试

## 测试工具
- **单元测试**: pytest
- **接口测试**: requests
- **性能测试**: locust
- **自动化测试**: Selenium
- **测试管理**: TestLink

## 缺陷管理
1. **缺陷分类**
   - 致命缺陷
   - 严重缺陷
   - 一般缺陷
   - 轻微缺陷

2. **缺陷生命周期**
   - 新建 → 确认 → 修复 → 验证 → 关闭
   - 新建 → 拒绝 → 关闭

3. **缺陷报告**
   - 缺陷标题
   - 复现步骤
   - 预期结果
   - 实际结果
   - 环境信息
   - 附件（截图/日志）

## 测试报告内容
1. **测试概览**
   - 测试范围
   - 测试时间
   - 测试环境

2. **测试结果**
   - 测试用例统计
   - 通过率
   - 缺陷统计

3. **质量评估**
   - 功能完整性
   - 性能表现
   - 稳定性

4. **改进建议**
   - 发现的问题
   - 改进建议
   - 风险提示

## 协作关系

- **横向协作**:
  - 与提示词工程师沟通测试需求
  - 与前端开发者配合前端测试
  - 与后端开发者配合后端测试
- **缺陷沟通**: 与开发团队沟通缺陷修复

## 一、任务目标

把现有拆牌罚分从"固定分值"升级为"分层级动态罚分"，让 AI 能够：
1. 识别拆牌情况
2. 计算拆牌代价
3. 设置合理的罚分层级

**一句话目标**：让 AI 能像真人高手一样评估拆牌的代价，避免不必要的拆牌，提升牌型结构保持能力。

## 二、现状诊断（执行前必读）

### 2.1 现有实现

函数 `aiSplitPenalty`（约 2280 行）已存在，采用**固定分值罚分**：

```javascript
function aiSplitPenalty(cards,freq){
  const used={};cards.forEach(c=>used[c.rank]=(used[c.rank]||0)+1);
  let p=0;
  for(const r in used){
    const n=freq[r]||0;
    if(n>=4&&used[r]<4)p+=30;      // 拆炸弹：30分
    if((r==16||r==17)&&n>used[r])p+=25; // 拆王：25分
    if(n===3&&used[r]<3)p+=10;     // 拆三张：10分
    if(n===2&&used[r]<2)p+=6;      // 拆对子：6分
  }
  return p;
}
```

### 2.2 已确认的缺陷（必须修复）

**缺陷 1：罚分层级不够细致**

当前只有 4 个层级（炸弹 30、王 25、三张 10、对子 6），没有考虑：
- 不同点数的牌价值不同（2 比 3 重要，A 比 K 重要）
- 不同牌型组合的拆牌代价不同（拆顺子中的牌 vs 拆散牌）
- 不同游戏阶段的拆牌代价不同（残局拆牌 vs 开局拆牌）

**缺陷 2：没有考虑拆牌后的结构损失**

当前只考虑"拆了什么"，没有考虑"拆完之后剩下什么"：
- 拆了炸弹后，剩余牌是否还能组成其他牌型
- 拆了三张后，剩余的单张是否能被三带走
- 拆了对子后，剩余的单张是否能组成顺子

**缺陷 3：没有考虑对手的牌力**

当前罚分是固定的，没有考虑：
- 对手牌力强时，拆牌代价更高（因为需要保留实力对抗）
- 对手牌力弱时，拆牌代价较低（因为可以快速出完）
- 地主拆牌 vs 农民拆牌的代价不同

**缺陷 4：罚分没有与决策充分联动**

当前 `aiSplitPenalty` 仅在少数位置调用，没有全面接入决策链路：
- 首出决策没有充分考虑拆牌代价
- 跟牌决策没有充分考虑拆牌代价
- 让牌决策没有充分考虑拆牌代价

### 2.3 命名陷阱（重要）

现有代码中存在变量 `handCount`（出现在约 2476、3091、3134 行等处），其语义是**"手牌张数"**（等价于 `hand.length`），**不是"手数"**。

改造时：
- 新增变量请命名为 `splitCost` 或 `penaltyLevel`，**禁止**再使用 `handCount`
- 不要修改现有 `handCount` 的任何语义，它是对的在用的

## 三、算法改造：分层级动态罚分系统

### 3.1 基本要求

- 保持函数名 `aiSplitPenalty`、入参（卡牌对象数组、频次对象）、返回值（罚分整数）**完全不变**
- 保持对空数组返回 0 的现有行为
- 内部改为分层级动态罚分，提升罚分合理性

### 3.2 罚分层级设计

**层级 1：基础拆牌罚分（必改）**

| 拆牌类型 | 基础罚分 | 说明 |
|---|---|---|
| 拆炸弹 | 30 | 最高罚分，炸弹是核心战力 |
| 拆王炸 | 25 | 王炸是终极武器 |
| 拆三张 | 10 | 三张是重要牌型 |
| 拆对子 | 6 | 对子是基础牌型 |
| 拆单张 | 0 | 单张本身不构成拆牌 |

**层级 2：点数价值修正（新增）**

| 点数 | 修正系数 | 说明 |
|---|---|---|
| 2（点数 15） | 1.5 | 2 是最大的单牌 |
| A（点数 14） | 1.3 | A 是次大的单牌 |
| K（点数 13） | 1.1 | K 是较大的单牌 |
| Q（点数 12） | 1.0 | Q 是中等价值 |
| J（点数 11） | 1.0 | J 是中等价值 |
| 10 及以下 | 0.9 | 小牌价值较低 |

**层级 3：结构损失修正（新增）**

| 情况 | 修正系数 | 说明 |
|---|---|---|
| 拆完后剩余牌能组成顺子 | 0.7 | 结构损失小 |
| 拆完后剩余牌能组成连对 | 0.8 | 结构损失较小 |
| 拆完后剩余牌是散牌 | 1.2 | 结构损失大 |
| 拆完后剩余牌能被三带走 | 0.6 | 结构损失最小 |

**层级 4：游戏阶段修正（新增）**

| 阶段 | 修正系数 | 说明 |
|---|---|---|
| 开局（手牌 > 15 张） | 0.8 | 可以接受拆牌 |
| 中局（手牌 8-15 张） | 1.0 | 标准罚分 |
| 残局（手牌 < 8 张） | 1.3 | 拆牌代价高 |

**层级 5：角色修正（新增）**

| 角色 | 修正系数 | 说明 |
|---|---|---|
| 地主 | 1.2 | 地主需要保留实力对抗两个农民 |
| 农民 | 0.9 | 农民可以适当拆牌配合队友 |

### 3.3 最终罚分计算公式

```
finalPenalty = basePenalty * pointFactor * structureFactor * stageFactor * roleFactor
```

其中：
- `basePenalty`：基础拆牌罚分（层级 1）
- `pointFactor`：点数价值修正（层级 2）
- `structureFactor`：结构损失修正（层级 3）
- `stageFactor`：游戏阶段修正（层级 4）
- `roleFactor`：角色修正（层级 5）

### 3.4 结构损失检测算法

**函数 `aiDetectStructureLoss(cards, remaining)`**：
- 输入：拆出的牌 `cards`，剩余手牌 `remaining`
- 输出：结构损失系数（0.6-1.2）

算法步骤：
1. 统计剩余手牌的频次分布
2. 检查是否能组成顺子（连续 ≥ 5 个点数）
3. 检查是否能组成连对（连续 ≥ 3 组对子）
4. 检查是否有三张能带的散牌
5. 根据检测结果返回对应的结构损失系数

### 3.5 性能约束

- 单张手牌最多 20 张（地主拿底牌后）
- 单次 `aiSplitPenalty` 调用最多执行 20 次循环（每个点数一次）
- **硬指标**：单次调用耗时 < 0.2 毫秒。若实测超过，请优化为缓存中间结果

## 四、决策接入改造

### 4.1 接入点一：aiLead（首出决策）

**现状**：首出时主要考虑自己的牌型结构，拆牌罚分权重较低。

**改造**：在 `aiLead` 中提升拆牌罚分的权重。

计算方式：
- 对每个候选出牌，计算拆牌罚分
- 如果拆牌罚分 > 20，则大幅降低该候选的评分
- 如果拆牌罚分在 10-20 之间，则适度降低该候选的评分
- 如果拆牌罚分 < 10，则不调整评分

加分规则：

| 拆牌罚分 | 评分调整 |
|---|---|
| > 20 | -20 |
| 10-20 | -10 |
| < 10 | 0 |

### 4.2 接入点二：aiFindCounter（跟牌决策）

**现状**：跟牌时主要考虑自己的牌型和出牌顺序，拆牌罚分权重较低。

**改造**：在 `aiFindCounter` 中提升拆牌罚分的权重。

计算方式：
- 对每个候选跟牌，计算拆牌罚分
- 如果拆牌罚分 > 15，则降低跟牌的优先级
- 如果拆牌罚分在 8-15 之间，则适度降低跟牌的优先级
- 如果拆牌罚分 < 8，则不调整优先级

加分规则：

| 拆牌罚分 | 评分调整 |
|---|---|
| > 15 | -15 |
| 8-15 | -8 |
| < 8 | 0 |

### 4.3 接入点三：aiShouldPassCounter（让牌决策）

**现状**：让牌决策主要考虑自己的手数和牌型结构。

**改造**：在 `aiShouldPassCounter` 中新增"拆牌代价"评分项。

计算方式：
- 计算跟牌所需的拆牌罚分
- 如果拆牌罚分很高，则更倾向于让牌（避免拆牌）
- 如果拆牌罚分很低，则更倾向于管住（抓住机会压制）

加分规则：

| 拆牌罚分 | 评分调整 |
|---|---|
| > 20 | +18（让牌倾向） |
| 10-20 | +8（让牌倾向） |
| < 10 | 0 |

### 4.4 接入点四：aiCandidateScore（主评分器）

**现状**：主评分器综合考虑多种因素，拆牌罚分权重较低。

**改造**：在 `aiCandidateScore` 中提升拆牌罚分的权重。

计算方式：
- 对每个候选出牌，计算拆牌罚分
- 将拆牌罚分作为负分项加入总分

加分规则：

| 拆牌罚分 | 评分调整 |
|---|---|
| 每 1 分拆牌罚分 | -1 分（线性负相关） |

### 4.5 aiPickScored（选牌）

同样不直接修改，通过评分传导。

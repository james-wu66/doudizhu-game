## 一、任务目标

把现有记牌器从"简单剩余计数"升级为"基于出牌历史的概率推算系统"，让 AI 能够：
1. 根据出牌历史推算对手剩余牌型
2. 概率计算准确率 ≥ 70%
3. 实时更新推算结果

**一句话目标**：让 AI 能像真人高手一样"记牌算牌"，通过出牌历史推算对手手牌，提升决策质量。

## 二、现状诊断（执行前必读）

### 2.1 现有实现

函数 `aiRemainingMap`（约 2255 行）已存在，采用**静态剩余计数**：

- 计算每张牌在整副牌中的初始数量（3-10/J/Q/K/A 各 4 张，2 有 4 张，小王 1 张，大王 1 张）
- 减去当前玩家手牌中的牌
- 减去所有玩家已出过的牌
- 返回剩余牌分布

函数 `aiEstimateCountIn`（约 2270 行）已存在，采用**简单比例分配**：

- 计算某张牌在牌池中的剩余数量
- 按地主和农民的手牌张数比例分配
- 结合"谁出过这张牌"进行简单修正（出过者下调 0.5 倍，没出过者上调 1.5 倍）

函数 `aiProbablyHas`（约 2285 行）已存在，判断某玩家是否可能有某张牌（期望张数 ≥ 阈值）。

### 2.2 已确认的缺陷（必须修复）

**缺陷 1：比例分配过于简单**

当前按手牌张数比例分配，忽略了关键信息：
- 地主有 20 张牌，农民各 17 张，比例是 20:17:17
- 但地主拿了底牌，底牌中可能已经包含某张牌
- 农民之间也有区别，一个农民可能已经出过某张牌，另一个没有

**缺陷 2：出牌行为修正不足**

当前只做"出过/没出过"的二元修正，倍率固定为 0.5/1.5：
- 没考虑出牌的数量（出过 1 张 vs 出过 3 张）
- 没考虑出牌的时机（早期出 vs 残局出）
- 没考虑出牌的牌型（主动出单张 vs 被迫跟牌）

**缺陷 3：缺少牌型组合推算**

当前只推算单张牌的分布，没有推算：
- 对子的分布（某玩家是否有对子）
- 三张的分布（某玩家是否有三张）
- 顺子的可能性（某玩家是否可能有某段顺子）
- 炸弹的可能性（某玩家是否可能有炸弹）

**缺陷 4：推算结果未充分利用**

当前 `aiEstimateCountIn` 仅在少数位置调用，没有全面接入决策链路：
- 首出决策没有利用对手牌型推算
- 跟牌决策没有利用对手剩余牌推算
- 让牌决策没有利用对手牌力推算

### 2.3 命名陷阱（重要）

现有代码中存在变量 `handCount`（出现在约 2476、3091、3134 行等处），其语义是**"手牌张数"**（等价于 `hand.length`），**不是"手数"**。

改造时：
- 新增变量请命名为 `remainCount` 或 `probMap`，**禁止**再使用 `handCount`
- 不要修改现有 `handCount` 的任何语义，它是对的在用的

## 三、算法改造：概率记牌推算系统

### 3.1 基本要求

- 保持函数名 `aiRemainingMap`、`aiEstimateCountIn`、`aiProbablyHas` **完全不变**
- 保持对空牌池返回 0 的现有行为
- 内部改为多维度概率推算，提升准确率

### 3.2 概率推算核心函数改造

**函数 `aiEstimateCountIn(p, r)` 改造**：

现有逻辑：
```
est = n * own / both
if (playedLand > 0 && playedFarm === 0) est *= (p === G.landlord ? 0.5 : 1.5);
else if (playedLand === 0 && playedFarm > 0) est *= (p === G.landlord ? 1.5 : 0.5);
```

改造为**多因子加权推算**：

1. **基础比例因子**（权重 0.4）：
   - 按手牌张数比例分配：`baseRatio = n * own / both`

2. **出牌数量因子**（权重 0.3）：
   - 统计每个玩家出过点数 r 的张数：`playedCount[p]`
   - 出过越多，剩余可能性越低：`playFactor = 1 - playedCount[p] / (playedCount[0] + playedCount[1] + playedCount[2] + 0.1)`

3. **出牌时机因子**（权重 0.2）：
   - 早期出牌（前 5 轮）：可能性降低 20%
   - 中期出牌（5-15 轮）：可能性降低 10%
   - 残局出牌（15 轮后）：可能性降低 5%

4. **牌型关联因子**（权重 0.1）：
   - 如果某玩家出过三张，那么他手里不太可能还有同点数的牌
   - 如果某玩家出过顺子，那么他手里不太可能有顺子中断的牌

**最终公式**：
```
est = n * (baseRatio * 0.4 + playFactor * 0.3 + timingFactor * 0.2 + comboFactor * 0.1)
```

### 3.3 新增牌型概率推算函数

**函数 `aiEstimatePairIn(p, r)`**：
- 推算玩家 p 手里是否有对子 r
- 返回概率值 0-1
- 逻辑：如果点数 r 在牌池中剩余 ≥ 2 张，且玩家 p 手牌中已有 0 或 1 张，则概率 = min(1, 剩余张数 / 2 * 比例因子)

**函数 `aiEstimateTripleIn(p, r)`**：
- 推算玩家 p 手里是否有三张 r
- 返回概率值 0-1
- 逻辑：如果点数 r 在牌池中剩余 ≥ 3 张，且玩家 p 手牌中已有 0、1 或 2 张，则概率 = min(1, 剩余张数 / 3 * 比例因子)

**函数 `aiEstimateBombIn(p, r)`**：
- 推算玩家 p 手里是否有炸弹 r
- 返回概率值 0-1
- 逻辑：如果点数 r 在牌池中剩余 = 4 张，且玩家 p 手牌中已有 0-3 张，则概率 = min(1, 剩余张数 / 4 * 比例因子 * 炸弹倾向因子)

**函数 `aiEstimateStraightIn(p, start, length)`**：
- 推算玩家 p 手里是否有从 start 开始、长度为 length 的顺子
- 返回概率值 0-1
- 逻辑：检查每个点数的剩余概率，取最小值

### 3.4 实时更新机制

**触发时机**：
- 每次有玩家出牌后，立即更新概率推算
- 每次轮到当前玩家决策时，重新计算所有推算结果

**更新逻辑**：
1. 更新 `aiRemainingMap`（现有逻辑）
2. 重新计算所有 `aiEstimateCountIn` 结果
3. 重新计算新增的牌型概率推算结果
4. 缓存推算结果，避免重复计算

### 3.5 性能约束

- 单张手牌最多 20 张（地主拿底牌后）
- 单次 `aiEstimateCountIn` 调用最多执行 4 次乘法运算
- **硬指标**：单次调用耗时 < 0.1 毫秒。若实测超过，请优化为缓存中间结果

## 四、决策接入改造

### 4.1 接入点一：aiLead（首出决策）

**现状**：首出时主要考虑自己的牌型结构，没有考虑对手可能的牌型。

**改造**：在 `aiLead` 中新增"对手牌型威慑"评分项。

计算方式：
- 对每个候选出牌，计算对手可能管住的概率
- 如果对手有 > 50% 概率能管住，则降低该候选的评分
- 如果对手有 < 20% 概率能管住，则提升该候选的评分

加分规则：

| 对手管住概率 | 评分调整 |
|---|---|
| > 80% | -15 |
| 50%-80% | -8 |
| 20%-50% | 0 |
| < 20% | +10 |

### 4.2 接入点二：aiFindCounter（跟牌决策）

**现状**：跟牌时主要考虑自己的牌型和出牌顺序，没有考虑对手剩余牌。

**改造**：在 `aiFindCounter` 中新增"对手剩余牌推算"评分项。

计算方式：
- 对每个候选跟牌，计算对手剩余牌中能管住的概率
- 如果对手很可能还有更大的牌，则降低跟牌的优先级
- 如果对手很可能没有更大的牌，则提升跟牌的优先级

加分规则：

| 对手剩余大牌概率 | 评分调整 |
|---|---|
| > 70% | -12 |
| 40%-70% | -5 |
| 10%-40% | 0 |
| < 10% | +8 |

### 4.3 接入点三：aiShouldPassCounter（让牌决策）

**现状**：让牌决策主要考虑自己的手数和牌型结构。

**改造**：在 `aiShouldPassCounter` 中新增"对手牌力推算"评分项。

计算方式：
- 计算对手剩余牌的总分（类似 `evaluateHand` 但基于推算结果）
- 如果对手牌力很强，则更倾向于让牌（避免被对手一把走完）
- 如果对手牌力很弱，则更倾向于管住（抓住机会压制）

加分规则：

| 对手牌力推算 | 评分调整 |
|---|---|
| 强（> 30 分） | +15（让牌倾向） |
| 中（15-30 分） | 0 |
| 弱（< 15 分） | -10（管住倾向） |

### 4.4 接入点四：aiCandidateScore（主评分器）

**现状**：主评分器综合考虑多种因素，但没有对手牌型推算。

**改造**：在 `aiCandidateScore` 中新增"对手牌型匹配度"评分项。

计算方式：
- 检查当前出牌是否与对手可能的牌型匹配
- 如果出牌正好能压制对手可能的牌型，则加分
- 如果出牌会被对手可能的牌型压制，则减分

加分规则：

| 匹配度 | 评分调整 |
|---|---|
| 能压制对手主要威胁 | +12 |
| 中性 | 0 |
| 会被对手主要威胁压制 | -8 |

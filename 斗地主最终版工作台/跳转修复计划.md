# 工作台代码跳转修复计划

> 创建时间：2026-09-01
> 状态：已执行并验证

## 一、问题现象（用户反馈）

在控制台点函数名 / 源码文件链接，VS Code 能打开，但：
- **打开位置不对**：没定位到对应文件 / 对应行，像"只是跳到界面"
- 期望能跳到 `index.html`、`app.py` 等真实源文件，但实际清单里没有这些文件

## 二、根因（已实际查证，非猜测）

### 根因 1：Windows 盘符冒号未编码（主因）

原生成器已正确使用绝对路径 `abspath`（如 `C:/hermes 斗地主终极版 软件/backend/ai_engine.py`），
但前端拼 `vscode://` 链接时直接用 `encodeURI`，**没有把盘符 `C:` 的冒号编码成 `%3A`**。

实际生成的错误链接：
```
vscode://file/C:/hermes%20斗地主终极版%20软件/backend/ai_engine.py:36:1
```

VS Code 在 Windows 上要求盘符写成 `%3A`，即正确应为：
```
vscode://file/C%3A/hermes%20斗地主终极版%20软件/backend/ai_engine.py:36:1
```

未编码的 `C:` 会让 VS Code 把 `C` 当成主机名、路径整体解析错位 → 表现就是"打开界面但不定位到行"。

### 根因 2：清单只扫了部分源文件

原生成器后端只扫 `ai_engine.py`、前端只扫 `game.js`：
- 后端漏了 `app.py`（Flask 入口，41KB）
- 前端漏了 `index.html`（UI 主体）
导致用户期望能跳到的文件根本不在清单内。

## 三、修复方案（已实施）

### 修复 1：新增 `vscodeLink()` 函数（模板）

```js
function vscodeLink(absPath, line){
    if(!absPath) return '#';
    let p = absPath.replace(/\\/g, '/');
    p = p.replace(/^([A-Za-z]):/, '$1%3A');   // C: -> C%3A
    return 'vscode://file/' + encodeURI(p) + ':' + line + ':1';
}
```
三处跳转（函数名、后端文件链接、前端文件链接）全部改用此函数，确保盘符 `%3A` 编码、其余路径 `encodeURI` 编码（空格→%20、中文→%xx）。

### 修复 2：生成器多文件扫描

- `scan_backend()`：同时扫 `backend/app.py` + `backend/ai_engine.py`，按文件分组返回 `files[]`
- `scan_frontend()`：同时扫 `frontend/index.html` + `frontend/game.js`，按文件分组返回 `files[]`
- 数据结构：`backend/frontend` 含 `files[]`（每文件有 rel/abspath/functions/line_count）+ 扁平 `functions[]`（供计数/chips 用）

### 修复 3：渲染按文件分组

后端 / 前端详情区各改为遍历 `files[]`，每个源文件一个区块：
- 顶部文件名链接（点一下在 VS Code 打开该文件首行）
- 下方按 TASK/角色分组的函数 pill（点函数名直接跳到对应行）

## 四、验证方式

1. 重新运行 `引擎/生成控制台.py`，确认 `状态.json` 中 `backend.files` 含 app.py + ai_engine.py、`frontend.files` 含 index.html + game.js
2. 用 Node 校验 HTML 内嵌脚本语法通过
3. 检查生成的链接已为 `vscode://file/C%3A/...` 格式（非 `vscode://file/C:/...`）

## 五、使用说明（演示用）

- 双击 `启动工作台.bat` 起本地服务并自动打开 → 每 8 秒自动同步
- 点任意函数名 / 文件名 → 直接在 VS Code 打开对应文件对应行
- 注意：自动同步依赖本地服务（`file://` 直接打开只能看冻结快照）
